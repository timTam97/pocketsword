# digits without re-prepending it — so "H430" became "0430", which is not a key.
# rawstr4.cpp:234-241 then snapped to a neighbouring entry and set no error,
# silently returning the wrong definition.
#
# The fix, and where it is asserted now:
# PSContentStoreTests.testDictionaryLookupCasingAndPaddingCases asserts
# dictEntry(module:"StrongsRealHebrew", key:"H430") == nil — a miss is a miss. The
# app was never affected in the first place, because osishtmlhref.cpp:66 strips the
# G/H prefix before the lookup, so it always passed the bare number.
#
# Do not delete this file to "clean up"; do not treat it as an expectation.
